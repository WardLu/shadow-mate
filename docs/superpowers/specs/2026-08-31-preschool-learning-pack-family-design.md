# Shadow Mate 学前学习包体系设计

状态：Accepted

创建日期：2026-08-31

接受日期：2026-09-01

## 1. 决策摘要

Shadow Mate 对家长呈现一套学前学习系统，内部使用同一学习引擎承载三个阶段学习包：

| 产品名称 | 学习阶段 | 建议年龄 | 当前范围 |
| --- | --- | --- | --- |
| 启蒙学习包 V1 | P1 发现 | 3–4 岁 | 整体体验和独立交付后续重新设计；既有 P1 80 字本次只作为 V2 基础内容使用 |
| 启蒙学习包 V2 | P2 启蒙 | 4–5 岁 | 原“启蒙学习包 V1”改名为 V2；当前汉字与轮动工作的主交付对象 |
| 启蒙学习包 V3 | P3 衔接 | 5–6 岁 | 使用 P3 汉字内容集，后续接入 |

V1、V2、V3 是产品学习包代号，不是内容发布版本。每个学习包仍要有独立的不可变 `contentVersion`，用于内容修订、审核和回滚。

## 2. 为什么不是三套独立系统

三个阶段真正变化的是课程内容边界、每日负荷、提示强度和学习方式，不是认证、导航、打卡、同步、打印、语音和复习基础设施。Shadow Mate 应复用：

- 同一家庭和 learner profile；
- 同一语文、数学、英语、绘本模块入口；
- 同一 local-first 状态和云同步；
- 同一内容选择和打印接口，以及适用于原子学习项的复习调度契约；
- 同一成长记录和今日打卡语义。

阶段差异由“内容目录 + 阶段策略”表达，不复制页面或状态机。

## 3. 学习包、内容集与适应策略

```text
学前学习系统
├── 启蒙学习包 V1 / P1
├── 启蒙学习包 V2 / P2
└── 启蒙学习包 V3 / P3
        │
        ├── 语文内容集
        ├── 数学内容集
        ├── 英语内容集
        └── 绘本内容集
                │
                └── 阶段内适应策略 + SM-2 复习调度
```

内容集决定“允许学什么、首次在哪个阶段引入”；适应策略决定“今天学多少、需要多少提示”；SM-2 决定“已经接触过的原子学习项何时复习”。三者不能互相替代。

### 3.1 累计内容池与首次引入

阶段内容池是累计的：

```text
V1 / P1 可用汉字池 = P1 首次引入 80 字
V2 / P2 可用汉字池 = P1 80 字 + P2 首次引入 120 字 = 200 字
V3 / P3 可用汉字池 = P1 80 字 + P2 120 字 + P3 首次引入 200 字 = 400 字
```

`firstExposureStage` 表示课程编排和审核归属，不表示某个儿童已经接触或掌握该内容。儿童直接从 V2 / P2 开始时，系统不能假定其已经学过 P1 的 80 字；这些字仍以“基础内容”身份进入新内容队列。

MVP 后的完整 V2 默认每天最多预留 1 个新内容名额给未接触的 P1 基础字，其余新内容名额来自 P2；P1 基础字耗尽后，全部新内容名额用于 P2。已经接触过的内容不再占用新内容名额，只按复习计划进入队列。MVP Pilot 不实现这套 P1/P2 混排。

这里要区分“课程目标池”和“当前激活内容版本”：课程目标池定义 V2 最终应覆盖的累计 200 字；某个 `contentVersion` 可以先以较小的、经过审核的 Pilot 子集激活。Pilot 子集不是完整 V2，也不能把未包含的目标字写成已掌握。

### 3.2 MVP 与完整课程的内容政策

当前 MVP 只验证字帖轮动闭环，不实现 SM-2 到期复习：

- Pilot 至少包含 32 个唯一、可书写的稳定内容项，覆盖至少 15 个 `dayKey`；
- 每日输出 4 个练写行，每行只有一个目标字；
- 同一字帖当天稳定，过去 7 个 `dayKey` 内尽量不重复；Pilot 的 32 个内容项足以在 4 行/天的策略下保持 7 日无重复；
- 跳过某天不补生成，也不把未打开日期算作失败；
- MVP 的完成记录只表示字帖完成，不生成 SM-2 复习评分。

完整 V2 在 MVP 后再接入：每日最多 2 个新字、最多 4 个到期复习目标、D+1/D+3/D+7/D+14/D+30 复习间隔、复习压力控制和可更正的家长评分。上述规则不作为当前 MVP 验收门槛。

## 4. 各模块应有的阶段差异

当前代码中的汉字、英语词汇、数学题型和绘本书单都是薄的静态集合，尚未形成完整的跨模块学习包。后续内容调优应按以下方向进入 roadmap：

| 模块 | P1 / V1 | P2 / V2 | P3 / V3 |
| --- | --- | --- | --- |
| 汉字 | 图、物、听音和书写准备；既有 P1 80 字本次只作为 V2 基础内容，不实现 V1 教学体验 | 图 → 词 → 字、简单描写、识字复习 | 字 → 短句、独立识别、更多书写准备 |
| 英语 | 具体事物听辨和跟读 | 主题词汇、简单搭配和双语概念 | 简单句、场景表达和阅读准备 |
| 数学 | 数量感、分类、形状和空间 | 比较、分解组合和简单运算 | 更大数域、规律、应用场景和入学准备 |
| 绘本 | 看图、听故事和指认 | 重复阅读、简单问答和顺序理解 | 复述、预测、因果和自主阅读准备 |
| 写字 | 控笔、线条和基本动作 | 规范笔画、淡描和简单字形 | 结构观察、临摹和少量独立书写准备 |

这张表定义调优方向，不代表上述内容已经存在，也不把跨模块丰满化纳入当前汉字轮动实现。

## 5. 年龄适应与阶段选择

年龄是推荐入口，不是能力判定。当前 learner profile 只有“学前”档位，没有生日或 3–4/4–5/5–6 的细分；因此系统不能假装已经具备自动年龄判断。

第一阶段采用家长选择或确认学习阶段：

- 默认已有启蒙体验迁移到 V2 / P2；
- 家长可以改选适合当前孩子的阶段；
- 不新增生日、学校或其他儿童敏感字段；
- 学习阶段是 learner profile 级的持久设置，在本机和云端状态中按学习者隔离；
- 阶段变化只改变以后允许引入的新内容，不清空历史、不重写首次接触记录；
- 已经接触过的内容即使不属于新阶段的新内容边界，也继续按原计划复习；
- 阶段内由适应策略调整每日负荷，不因一次表现自动跨阶段。

系统可以提示家长考虑调整阶段，但不能根据生日、完成率或一次测验自动升级或降级。

三个边界场景采用固定语义：

- 旧用户首次获得阶段设置时默认 V2 / P2，但其 P1 内容不会因此被写成已接触或已掌握；
- 从 V2 切到 V3 后，开始允许引入 P3 新内容，原有 P1/P2 复习继续；
- 从 V3 切回 V2 后，停止引入尚未接触的 P3 内容，已经接触过的 P3 内容仍保留并继续复习。

## 6. 每日新内容与复习负荷

P1、P2、P3 的目标内容量不同，不能共享一个全局“每日 2 个新字”常量。每个学习包定义自己的新内容范围，满足：

```text
V1 / P1 的每日新内容上限 < V2 / P2 < V3 / P3
```

汉字阶段内容池沿用课程设计中的首次引入规模：P1 80、P2 新增 120、P3 新增 200。每日新字数量由学习包策略配置；当前工程不能从总字数直接推导一个永久常量。

MVP 后完整 V2 / P2 的首版默认策略：

```yaml
policyId: hanzi-p2-daily-v1
defaultNewItems: 2
hardMaxNewItems: 3
reviewBudget: 4
coreItemBudget: 6
```

以上是完整 V2 / P2 在 MVP 后接入学习进度时的首版策略，不是当前 MVP 的验收门槛。其中 `hardMaxNewItems` 是策略和后续实验的安全上限，不代表每天默认推送 3 个新字，也不在首版向家长开放手动加量入口。V1 / P1 和 V3 / P3 的具体数值待各自内容与体验设计时冻结；三阶段仍以 V1 默认负荷低于 V2、V3 默认负荷高于 V2 为设计目标。

每日调度顺序：

1. 先按 `nextReviewDay`、稳定内容 ID 排序，取最多 4 个已经到期的复习项；
2. 到期项为 0–2 个时加入最多 2 个新字，到期项为 3 个时加入最多 1 个新字，到期项达到 4 个或更多时暂停新字；
3. 每天汉字核心任务不超过 6 个目标；未装入当天任务的到期项保持到期状态，后续继续优先，不集中补发；
4. 跳过学习日不集中补发大量新内容；
5. 新内容必须来自当前阶段累计课程池；复习内容来自该学习者已经接触过的稳定内容项，不因后来切换阶段而丢失。

## 7. MVP 后：Quick-flomo SM-2 的接入边界

Shadow Mate 采用独立、可测试的 `sm2-compat-v1` 状态转换契约。该契约以 Quick-flomo 的测试模型为兼容来源，但不调用 Quick-flomo 的 `vocabulary-manager`、Pro 权益接口或 `vocabulary` 表，也不复制当前服务端路径中与测试不一致的实现。

共同语义：

- `again = 0`、`hard = 3`、`good = 4`、`easy = 5`；
- 初始 `easeFactor = 2.5`，最低为 1.3；
- 新内容首次引入时建立 `intervalDays = 1`、`reviewCount = 0`、`consecutiveCorrect = 0`，并令 `nextReviewDay = introducedDay + 1`；首次引入本身不是复习成功；
- `quality < 3` 时，`intervalDays = 1`、`reviewCount = 0`、`consecutiveCorrect = 0`；
- `quality >= 3` 时，第一次成功间隔为 1 天，第二次为 6 天，之后使用评分前的 ease factor 计算 `round(intervalDays × previousEaseFactor)`，再把 `reviewCount` 加 1；
- `good` 和 `easy` 增加 `consecutiveCorrect`，`hard` 保持该值，`again` 将其清零；
- 间隔和计数更新后，使用评分前的 ease factor 计算 `easeFactor = max(1.3, previousEaseFactor + 0.1 - (5-q) × (0.08 + (5-q) × 0.02))`；
- `nextReviewDay = reviewDay + intervalDays`，到期项按该字段进入当天复习队列。

Shadow Mate 的调度对象是 `learner profile + stable content item ID`，不是 Quick-flomo 的用户词汇行。首版不采用 Quick-flomo 的 `mastery_level`、`is_mastered` 或“掌握后 365 天”规则；持续表现稳定的内容只通过正常 SM-2 间隔降低频率，不退出课程历史。Quick-flomo 服务端是否修正为同一契约是独立任务，不阻塞 Shadow Mate 使用已冻结的纯函数与共享测试向量。

当前 SM-2 只承诺用于具有稳定 ID、可以得到明确复习结果的原子学习项，例如汉字、词汇或数学事实。绘本阅读、完整数学活动和每日模块打卡不强制套用这一评分模型。

## 8. MVP 打卡与后续复习更正

“今日打卡”和“复习记录”是两个不同概念：

- 今日打卡保持当前可撤销交互，用于成长记录；
- 写完一张字帖只代表完成练习，不能自动写入 `good`；
- 取消今日打卡不会静默删除已经存在的复习结果。

以下属于 MVP 后的复习交互，不作为当前 MVP 门槛：

- 儿童完成认读、听音找字或回忆检查后，由家长在当前家长会话中确认 `again`、`hard`、`good` 或 `easy`；
- 儿童可以执行点击或选择动作，但复习评分归属于家长确认的学习会话，不建立儿童独立账号；
- SM-2 只有收到这条明确、带 learner profile 和稳定内容 ID 的复习结果后才更新；
- 同一内容同一天的误评分允许更正，保留最后一次家长确认的结果作为当天有效记录；
- 更正后从更正点按时间顺序重放该内容后续有效记录，重新计算 SM-2 状态。

因此不再使用“完成历史不可撤销”作为产品或技术要求。

## 9. 交付分层：MVP、MVP 后与长期体系

本规范的 `Accepted` 表示产品架构和交付边界已经确定，不表示所有目标能力已经实现。当前 MVP 只验证“家长每天打开一张稳定、可打印、会轮换的汉字字帖”这一核心闭环。

### 9.1 当前 MVP：V2 Pilot + SHA-16

MVP 默认使用启蒙学习包 V2 / P2，但不增加阶段选择页面，也不要求一次性交付完整 200 字课程：

- 提供不可变的 `hanzi-v2-pilot-1` 内容版本；它是 V2 的试运行内容版本，不冒充完整 V2 课程；
- Pilot 至少包含 32 个唯一、可书写的稳定内容项，覆盖至少 15 个 `dayKey`；实际数量以 manifest 为准，不写死在轮动逻辑中；
- 替换当前 `WRITE_WORDS.slice(0, 4)` 固定展示，接入 SHA-16 的版本化、适龄、稳定去重轮动；
- 保持 SHA-15 已确认的“同日保持当前字帖、次日才轮换”语义；
- 屏幕和打印都消费同一份 assignment snapshot，打印不重新解析、不推进轮动、不产生额外完成记录；
- 复用现有 local-first、每日打卡、离线、登录和 learner profile 隔离边界；
- 不新增内容后台、生产内容表或 Supabase 迁移。

MVP 验收不包括：

- 完整 V2 累计 200 字及 P1/P2 混排；
- `sm2-compat-v1` 复习评分、复习历史重算和每日复习预算；
- 阶段选择、阶段切换和自动年龄适应；
- 普通话离线语音、跨模块内容丰满化、V1/P1 和 V3/P3 接入。

### 9.2 MVP 后第一阶段：学习进度与完整 V2

MVP 核心闭环稳定后，再按独立任务接入：

- `sm2-compat-v1` 纯函数、共享测试向量、家长确认评分和复习队列；
- V2 累计汉字内容集：既有 P1 80 字基础内容 + P2 首次引入 120 字；
- V2 每日新字预算、复习压力控制和 P1 基础内容混排；
- learner profile 级阶段设置、阶段切换和既有复习历史保留；
- 普通话系统语音和必要的内容质量/来源审核。

### 9.3 长期体系

以下继续进入 roadmap，不阻塞当前 MVP 或 MVP 后第一阶段：

- 启蒙学习包 V1 / P1 的整体重做、独立体验和 P1 汉字教学设计；
- 启蒙学习包 V3 / P3 的产品接入；
- 英语、数学、绘本、诗词和非汉字语文内容的全面扩充；
- 内容编辑后台、AI 自由选课或新的生产内容表。

## 10. Roadmap 约束

跨模块内容丰满化是独立产品工作流，必须先做现状盘点、阶段目标和内容质量标准，再分别设计内容集。它不应以“顺便多加一些静态数组”的方式混入汉字轮动任务。

持久路线记录见 [产品路线](../../product-direction.md)。

Roadmap 至少包含：

1. V2 / P2 各模块内容深度审计与补全；
2. V1 / P1 整体学习体验重新设计，P1 汉字单独评审；
3. V3 / P3 内容接入与幼小衔接体验；
4. 英语、数学、绘本和语文非汉字内容的阶段标签、难度、主题、来源和审核；
5. 内容质量、版权、来源和版本发布门禁；
6. 真实家庭使用反馈后的阶段策略和每日负荷调优。

## 11. 验收原则

- 家长只看到一套连贯的学前学习体验，不需要理解三套技术系统。
- 启蒙学习包 V1、V2、V3 的名称和 P1、P2、P3 映射全局一致。
- 内容版本不会与学习包代号混用。
- V2 可用汉字池为累计 200 字；直接进入 V2 不会把 P1 的 80 字误判为已学会。
- 当前 MVP 只推进 V2 Pilot + SHA-16；完整 V2、SM-2、阶段选择、其他阶段和跨模块内容丰满化按交付分层推进。
- MVP 的字帖轮动、同日稳定、次日轮换、屏幕/打印 snapshot 和不同 learner 隔离必须成立。
- MVP 后才验收 V2 默认每天 2 个新字、最多 4 个到期复习目标、核心任务不超过 6 个。
- MVP 后的 `sm2-compat-v1` 评分、间隔、`reviewCount` 和更正规则具有唯一、可复现的状态转换结果。
- 打卡可撤销；MVP 后的复习记录可更正；不同 learner 的状态不串联。
