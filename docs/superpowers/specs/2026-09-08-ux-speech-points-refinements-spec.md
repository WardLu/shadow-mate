- **作者**：Antigravity

## 一、背景与问题定义

在上一轮全场景儿童语音朗读与成长闭环动效落地后，经真机与线上体验，发现以下 6 个需要深化的用户体验与逻辑细节：

1. **生字卡片播放交互异常**：点击识字打卡中的今日新字卡片（如“火”、“木”）时，播放逻辑直接重写了卡片的 `innerHTML`，导致卡片原本的生字拼音结构（`.big`、`.py`、`.label`）被破坏，变成单行挤压文本 `🔊 火huǒ火山`；
2. **朗读音量不一致**：使用 CDN 预录音频（Tencent TTS，含 Web Audio 增益与压缩器）与系统语音合成（Web Speech API Utterance，原始音量）时感知音量存在明显落差，需要基于当前设置的课程语音音量进行平衡对齐；
3. **字意行点读体验不一致**：在“今日图字学习·写字”卡片中，点击“字意行”（`字意：没有颜色、会流动的液体`）应当与点击右侧「🔊 朗读字意」按钮完全等同，联动发音；
4. **使用指南信息滞后**：应用内的“指南”页仅包含早期基础功能说明，缺少全场景儿童语音点读、积分好习惯闭环、心愿奖励兑现及音效/朗读音量调节的指引；
5. **积分历史明细缺乏“撤销”标记**：用户在当天撤销打卡（例如点击已扣分的“撒谎”进行撤销）时，最近明细中会同时显示 `撒谎 -10` 与 `撒谎 +10`，容易让家长和孩子误解为“因撒谎获得了加分”；
6. **奖励兑换操作冗余且文案不够准确**：在心愿处于待兑现状态时，卡片右侧同时展示了置灰的 `待兑现` 胶囊按钮、绿色的 `标记已兑现` 按钮和红色的 `取消兑换` 按钮，界面多余且认知混乱；文案需统一升级为更具仪式感的「确认兑现」。

## 二、详细设计方案

### 1. 生字卡片与点读元素播放交互优化（保留样式，仅增播放动效）

#### 核心痛点
`src/app.js` 中的 `speak(t, button)` 函数原本假定 `button` 是一个标准音频小按钮（`<button class="btn btn-sm">`），在播放时执行了：
```javascript
button.innerHTML = buttonContent("volume", label); // 覆盖 DOM
```
而在播放结束时执行：
```javascript
button.innerHTML = buttonContent("volume", originalLabel); // 覆盖 DOM
```
导致包含多行子元素布局的 `.mini-card` 内部结构彻底丢失。

#### 设计方案
1. **区分容器型点读元素与纯文本小按钮**：
   - 当 `speak()` 传入的触发目标属于容器型点读元素（拥有 `.speech-tap`、`.mini-card`，或其子节点包含元素节点 `target.firstElementChild !== null` 且不属于纯按钮时），**严禁直接修改其 `innerHTML`**。
   - 保留容器内部全部 DOM（汉字大字 `.big`、拼音 `.py`、组词 `.label` 等），只控制状态属性与动效 Class。
2. **增加儿童友好的播放中视觉交互**：
   - 播放中：为目标元素添加 `aria-busy="true"` 与 `.speech-playing` 类名。
   - 播放完毕/中断：移除 `aria-busy` 与 `.speech-playing` 类名。
   - 视觉动效设计：在 `src/app.css` 中为 `.speech-playing` 添加温柔的呼吸光晕与微弱缩放脉冲（微幅律动，如 `animation: pulse-gentle 1.2s ease-in-out infinite`），既让孩子明确知道“这个字正在读给它听”，又 100% 保持卡片原有布局不改变。

---

### 2. 朗读音量平衡与统一当前设置

#### 核心痛点
- CDN 预录音频（`tencent-tts-player.js`）走 Web Audio API 处理，配置了 DynamicsCompressor（阈值 -20dB）与感知倍率 `calculatePerceptualSpeechGain`（基准 1.5x 增益）。
- 兜底系统语音（`SpeechSynthesisUtterance`）由操作系统原生合成，直接使用 `utterance.volume = Math.max(0, Math.min(1, speechVolume))`（默认 0.6），无任何增益或压缩。
- 两者在相同 60% 音量滑块下，CDN 发音响度显著高于系统发音，造成“听起来忽大忽小、音量不一”。

#### 设计方案
1. **校准两种语音源的感知音量曲线**：
   - 对齐基准响度：调整 CDN Web Audio 的基线增益与系统语音的映射关系，缩小动态压缩倍率差异；
   - 统一由 `soundEffects.getSpeechVolume()` 作为全局唯一音量数据源；
   - 在系统语音兜底播放时，将 `speechVolume` 映射至合适的系统发音音量，确保即使在切换发音源时，输出声级依然平稳一致；
2. **设置页「试听发音」统一化**：
   - 确保“设置”页面中的音量滑块变化时，试听预览严格遵从当前即时音量，并能如实反映各场景统一后的朗读音量大小。

### 3. 字意行点击朗读联动（等同「朗读字意」按钮）

#### 核心痛点
在写字练习卡片中，生字、组词、例句和书写口诀都有点击点读能力，但唯独“字意行”（`字意：...`）不支持点击朗读，且与右侧的「朗读字意」按钮未形成联动。

#### 设计方案
1. **DOM 结构增强**：
   - 在 `src/hanzi-writing-view.js` 的 `renderRow` 中，为 `.hanzi-meaning` 添加：
     - `role="button"`
     - `tabindex="0"`
     - `class="hanzi-meaning speech-tap"`
     - `data-hanzi-meaning-row` 与相关语义 `aria-label="点读字意：${characterMeaning}"`
2. **事件与播放联动**：
   - 点击字意行（或键盘 Enter/Space）时，直接触发对应行内的 `[data-hanzi-meaning-speak]` 逻辑（使用相同的 `${contentId}:meaning`、发音文本与语种）；
   - 触发时，字意行与「朗读字意」按钮同时进入播放激活状态（添加 `.speech-playing`），发音完毕同步恢复。

### 4. 使用指南信息全面同步更新

#### 核心痛点
`src/app.js` 的 `renderGuide()` 当前仅有基础的“快速上手”、“系统语音下载”、“家庭同步”与“添加到主屏幕”，完全脱离了当前丰富的学习点读、积分闭环与音效设置现状。

#### 设计方案
在 `renderGuide()` 中新增与完善以下核心板块：
1. **全场景儿童语音与点读功能使用指引**：
   - 语文：点击今日新字卡片听拼读组词；点击古诗任意行或标题听标准诵读；点击写字卡片中的概念头、词语胶囊、字意行、例句和笔顺口诀听语音辅导；
   - 数学：点击「读要求」、「读规则」按钮听语音播报题目要求；
   - 英语：点击「读指引」听拼读说明，点击往期单词标签直接听美式纯正发音。
2. **习惯积分与心愿兑换成长闭环指引**：
   - 积分激励：好习惯加分激励，需改进习惯温和提醒，支持即时撤销修正；
   - 心愿履约闭环：孩子消耗积分兑换心愿后进入“待兑现”，家长在实际生活中履行约定后点击「确认兑现」完成闭环；亦支持取消兑换返还积分；
   - 积分明细：展示完整收支与撤销记录，透明可信。
3. **声音与音量设置调节说明**：
   - 指南中说明“界面音效”与“课程语音”为独立音量控制，可按家庭环境随时在设置中调节。

### 5. 积分明细区分撤销记录

#### 核心痛点
在 `renderGrow()` 的“最近积分明细”列表中，当某条记录是通过撤销产生的反向记录时（`entry.entry_type === "adjustment"` 或 `entry.metadata?.undo_of`），依然只显示原名称（如 `撒谎`），且分数为正值 `+10`，导致明细阅读体验出现歧义。

#### 设计方案
1. **判定规则**：
   - 如果条目满足以下任一条件，即识别为撤销/冲正条目：
     - `entry.metadata?.undo_of` 存在
     - `entry.entry_type === "adjustment"`
     - `entry.note` 包含 `"撤销"`
     - 兑换取消退款记录（`entry.entry_type === "refund"` 或 `entry.metadata?.cancel_of`）
2. **显示文案格式化**：
   - 普通加减分：显示 `${item_name}`，如 `撒谎`（-10 分）或 `认真完成学习`（+3 分）；
   - 撤销动作：显示 `${item_name}（撤销）`，如 `撒谎（撤销）`（+10 分）或 `认真完成学习（撤销）`（-3 分）；
   - 兑换退款：显示 `${item_name}（兑换取消）`（+N 分）；
3. **视觉一致性**：保留正分绿色、负分红色的清爽徽标，文案中清晰标注 `（撤销）`，彻底消除误解。

---

### 6. 奖励兑现文案优化与待兑现状态精简

#### 核心痛点
当心愿存在待兑现记录（`latest?.status === "pending"`）时，卡片右侧同时展示：
- `<button disabled>待兑现</button>`（多余且置灰）
- `<button>标记已兑现</button>`（文案偏技术化）
- `<button class="danger">取消兑换</button>`

#### 设计方案
1. **精简待兑现状态下的多余按钮**：
   - 在奖励处于待兑现（`status === "pending"`）时，**不渲染左侧的 `待兑现` 置灰按钮**；
   - 仅显示右侧操作动作：**「确认兑现」**（主操作，绿色）与 **「取消兑换」**（危险操作，红色次要按钮）；
   - 状态已在卡片正文或整体上下文中明确，避免“一个置灰标签 + 两个按钮”的冗余并排；
2. **文案更新**：
   - `标记已兑现` $\to$ **`确认兑现`**；
   - 异常重试时保持 `重试兑现`；
3. **非待兑现状态保持**：
   - 无待兑现记录时，展示积分消耗与 `兑换` 按钮（积分充足可点，不足置灰）；
   - 已兑现记录可再次发起兑换或按需撤销。

## 三、兼容性、安全性与测试计划

1. **Local-first 离线与同步兼容性**：
   - 积分明细展示变更仅为前端只读视图的呈现层优化（基于现有的 `entry_type`、`metadata` 与 `note`），不破坏底层的 Ledger Schema、Supabase 同步协议或离线 Outbox 队列；
   - 奖励兑换的兑现与取消操作完全沿用已有的事件派发与确认链路。
2. **自动化测试覆盖**：
   - **单元测试**：
     - 测试字意点读与文本净化逻辑；
     - 测试积分明细格式化函数对 `undo_of`、`adjustment`、`refund` 的标记解析。
   - **E2E 自动化测试**：
     - 验证点击今日生字卡片后，卡片内部 `.big`、`.py`、`.label` 元素依然完整存在，样式不崩溃，且触发了 `speech-playing`；
     - 验证点击字意行能正常触发字意语音朗读；
     - 验证打卡后撤销，在积分明细中正确展示 `（撤销）` 标签；
     - 验证发起兑换后，界面不显示多余的「待兑现」按钮，且按钮文案为「确认兑现」；
     - 验证指南页新板块已正确呈现。
